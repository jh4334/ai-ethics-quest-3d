# 하루와 사라진 이름: 탑다운 3D 동화 모험 재설계

상태: 구현 기준  
기준일: 2026-08-23

## 1. 제품 한 문장

금빛 실을 든 어린 기록자가 밤의 동화 섬을 직접 걷고, 먹물 괴물을 물리치며, 단서와 문양을 연결해 사라진 친구 하루의 이름을 되찾는 6장짜리 탑다운 3D 액션 어드벤처다.

고전 탑다운 모험의 `탐색 → 발견 → 도구 사용 → 문 열기 → 보스 → 선택` 문법만 참고한다. 특정 상업 게임의 이름, 캐릭터, 지도, 로고, 음악, 아이콘, 고유 퍼즐과 시각 자산은 복제하지 않는다.

## 2. 플레이 원칙

- 카메라는 플레이어를 위쪽 사선에서 따라간다. 화면은 회전시키지 않아 길 찾기가 쉽다.
- 기본 행동은 이동, 금빛 실 휘두르기, 거울잎 방어, 살펴보기 네 가지다.
- 체력이 모두 닳아도 진행 기록은 잃지 않는다. 가까운 등불에서 다시 일어난다.
- 전문 용어와 정답 점수는 없다. 지나치게 비춘 등불, 기운 저울, 이름을 삼킨 축제처럼 은유가 반복된다.
- 장 마지막 선택은 `지킨 것`과 `치른 것`을 함께 기록한다.

## 3. 핵심 루프

`마을 대화 → 두 단서 탐색 → 두 기억 문양 활성화 → 기억 열쇠 획득 → 기록문 개방 → 먹물 수호자 전투 → 가치 선택 → 다음 섬`

문은 열쇠 없이 열리지 않는다. 금빛 실은 가까운 먹물만 지우며 연타 재사용 대기시간이 있다. 거울잎을 공격 방향으로 들면 피해를 막는다. 퍼즐·단서·열쇠는 사망 뒤에도 유지해 난도를 낮춘다.

## 4. 6장 공간과 상징

| 장 | 탐색 공간 | 보스 은유 | 남는 질문 |
|---|---|---|---|
| 1 빈자리의 서랍 | 밤 교실 정원과 너무 넓은 등불 | 빈 이름을 먹는 먹물 수호자 | 어디까지 비춰도 되는가 |
| 2 저울나무가 기운 쪽 | 높이가 다른 다리와 뿌리 우편함 | 큰 숫자만 보는 저울벌레 | 남겨진 작은 이름을 보았는가 |
| 3 이름을 삼킨 축제 | 반딧불 등과 접힌 무대 | 손자국을 지우는 가면지기 | 빛을 만든 손은 누구인가 |
| 4 목소리를 입은 종이새 | 물 위 극장과 조용한 둥지 | 목소리를 베끼는 메아리새 | 익숙한 목소리가 진짜인가 |
| 5 손 없는 도장 | 세 겹 시계탑과 편지 창구 | 멈추지 않는 자동 도장 | 누가 멈추고 다시 보았는가 |
| 6 하얀 방의 반딧불 | 검은 리본 길과 하루의 방 | 이야기를 전부 삼키는 흰 먹물 | 누구에게 열쇠가 있어야 하는가 |

장마다 팔레트, 랜드마크, 적의 실루엣과 대사가 달라진다. 공통 규칙은 학습 부담을 줄이고, 공간 상징과 선택 결과가 의미를 바꾼다.

## 5. 카메라와 공간

- Perspective 42°, 플레이어 뒤 8m·위 10m에서 부드럽게 추적한다.
- 이동 영역은 X -8~8, Z -6~6의 작은 부유 섬이다.
- 닫힌 기록문은 충돌체다. 열린 뒤 북쪽 보스 정원으로 이동할 수 있다.
- 바닥은 종이 가장자리와 낮은 석재 길을 함께 써서 동화책과 실제 공간 사이의 느낌을 만든다.
- 캐릭터는 Kenney Mini Characters GLB, 가구·식생은 이미 기록된 CC0 에셋을 재사용한다.
- 적·문양·열쇠·기록문·금빛 실·거울잎은 프로젝트 고유 Three.js 메시다.

## 6. UI와 조작

| 행동 | 키보드 | 터치 |
|---|---|---|
| 이동 | WASD / 방향키 | 왼쪽 4방향 패드 |
| 금빛 실 | J | `실` 버튼 |
| 거울잎 방어 | K를 누르는 동안 | `잎` 버튼을 누르는 동안 |
| 살펴보기 | E | `보기` 버튼 |

- 상단 HUD는 장 번호, 제목, 목표, 생명 불씨, 열쇠 상태만 보여 준다.
- 가까운 대상이 있을 때 화면 아래에 한 문장 행동 안내를 낸다.
- 대화와 선택은 DOM으로 제공하고 Canvas 상태와 같은 의미를 읽을 수 있게 한다.
- 모든 주요 버튼은 44px 이상, 포커스가 보이며 색 외에 문양과 글자를 함께 쓴다.
- 390×844에서 가로 스크롤과 조작 겹침이 없어야 한다.

## 7. 결정성과 성능

- 게임 상태는 60Hz 고정 틱으로 갱신한다. 게임플레이 경로에서 `Math.random`을 쓰지 않는다.
- 플레이어·적 충돌과 공격 판정은 순수 JS 모듈에서 계산하고 Three.js 장면은 결과만 표현한다.
- 픽셀 비율 상한 1.75, 상시 그림자 없음, 기존 라이트 세 개 이내를 유지한다.
- 에셋 실패는 플레이를 막지 않고 오류 목록과 대체 메시를 남긴다.

## 8. 저장과 호환

- 기존 `ethics-quest-storybook3d-v1` 키를 유지하고 스키마만 v2로 정규화한다.
- v1의 단서와 선택은 손실 없이 복원한다.
- 현재 장의 위치, 생명, 퍼즐, 열쇠, 문, 보스 상태를 저장한다.
- `illustrated.html`, `reboot.html`, `legacy.html`은 롤백 경로로 유지한다.

## 9. 수용 기준

- 새 게임에서 실제 이동으로 두 단서와 두 문양을 찾고, 열쇠로 문을 열고, 보스를 쓰러뜨려 선택까지 갈 수 있다.
- 열쇠 전 문 잠김, 연타 방지, 정면 방어, 월드 경계, 부활 보존이 자동 테스트와 브라우저에서 확인된다.
- 키보드와 터치 모두 완주 가능하고 WebGL 실패 시 2D 보존판 안내가 보인다.
- 1440×900과 390×844 캡처에서 캐릭터, 이동 길, 문, 보스, HUD와 한국어가 분명하다.
- `npm test`, `npm run build`, `npm run smoke`, 전용 Playwright가 통과하며 콘솔·HTTP·에셋 실패가 0건이다.
