# H-17: NULL 6장 전면개선 실행계획

기준 커밋은 `origin/main`의 `c7e37d87`이다. 작업 브랜치는 `codex/h17-six-chapter-campus-overhaul`이며 `main` 병합은 사용자 승인 전까지 금지한다.

## 정본 결정

- 대상은 초등 5–6학년이다. 분위기는 스릴러지만 유혈·굴욕적 영상·도덕 점수를 사용하지 않는다.
- 구조는 장별 독립 캠페인과 장 내부의 열린 탐색 공간을 결합한다. 전체를 하나의 무제한 오픈월드로 만들지 않는다.
- 기존 1–4장 사건과 전투를 보존하고 새 5장 `증언 보관소`를 삽입한다.
- 기존 5장 `마지막 방송`은 6장으로 이동한다. `broadcast-queue`와 세 결말은 6장이 소유한다.
- `SECURE`, `PURGE`, `EXPOSE`는 증거 처리 행동이고 결말 점수가 아니다.

## 저장 v4 → v5 매핑

- 단일 계약 상수는 `SAVE_SCHEMA_VERSION = 5`, `CHAPTER_COUNT = 6`이다.
- 새 키 `h17.null.save.v5`, `h17.null.save.v5.tmp`를 사용한다. 기존 v4 문자열은 삭제·덮어쓰기하지 않는다.
- v4 장 1–4는 같은 장, 체크포인트, 증거, 신뢰, 설정을 유지한다.
- v4 장 5는 v5 장 6으로 이동한다. `chapter-5:*`는 알려진 접미사를 `chapter-6:*`로 변환한다.
- v4 `broadcast-queue` 증거의 장은 5에서 6으로 바꾼다.
- 기존 5장 완료자는 새 5장을 `legacy-grandfathered` 완료 처리해 결말과 이어하기를 잃지 않는다.
- 알 수 없는 v4 5장 체크포인트는 `chapter-6:broadcast-room`으로 복구하고 사용자 안내를 남긴다.
- 마이그레이션은 멱등이고 v4 원문은 항상 보존한다. 미래 v6와 손상 저장은 안전한 새 게임으로 연다.

`gateAttempts`는 `{ gateId, chapter, outcome }`만 저장한다. `outcome`은 `resolved|failed|unknown`이며 윤리 선택과 전투 패배를 구분한다. 보고서는 `unattempted|first-try|retry|struggling|unknown`을 파생하고 정답·도덕 점수를 만들지 않는다.

## P0 이전 자산·성능 예산

- 기본: Kenney Building/Suburban/Commercial/Furniture/Nature CC0에서 필요한 GLB만 선별한다.
- 표면: ambientCG CC0의 Grass001, Asphalt009, Bricks001, WoodFloor041, Concrete004, Metal009를 512/1024로 가공한다.
- GLB는 Meshopt를 우선 검토하고 텍스처는 KTX2 ETC1S/UASTC를 측정 후 채택한다. Draco와 중복 적용하지 않는다.
- 첫 화면 추가 3D 전송 ≤5MB, 내부 공간 지연 로드 ≤4MB, 동시 신규 텍스처 GPU 추정 96MB 이내를 목표로 한다.
- 출하 상한: 데스크톱 p95 16.7ms, 터치 33.3ms, draw calls 250, triangles 150k, 동적 light 4, particles 250, 20분 heap +10%, console 0.
- 공통 performance probe를 모든 production scene에 연결하고 각 슬라이스에서 측정한다.

## 실행 순서와 수용 기준

### 0. 계약과 RED

1. 정본 문서와 6장 카탈로그 계약을 갱신한다.
2. `reboot-save-v5`, `reboot-six-chapter-routing`, `reboot-learning-report`, `reboot-webgl-boot`, `reboot-assets` 실패 테스트를 먼저 만든다.
3. 테스트는 한국어 문장 전체가 아니라 ID, 상태, 순서, 시도 수, 결말 소유, 도덕 점수 부재를 검사한다.

### 1. v5 플랫폼

- v4 마이그레이션, v5 repository/codec, gate attempts, 1–6 라우팅을 구현한다.
- WebGL renderer 성공 뒤에만 입력·RAF·scene을 시작한다.
- renderer throw와 context loss에 접근 가능한 복구 화면을 표시한다.
- lifecycle은 `transition(sceneId)`에서 기존 scene의 `exit/dispose`와 RAF 단일성을 보장한다.

### 2. P0 1장 버티컬 슬라이스

- 환경 카탈로그·진행률·오류 placeholder·dispose를 구현하고 라이선스/manifest/실파일 일치 테스트를 통과한다.
- 부유 캠퍼스, 열린 교실, 명단탑, 운동장 트랙과 지문 장치, 도서관/기록보관소/행정동, 삭제 광선 유리 타워를 실제 3D로 만든다.
- 1440×900 데스크톱과 390×844 모바일에서 전체 조망, 실내, 전투, 결과를 캡처한다.
- 레퍼런스와 같은 크기로 비교하고 캐릭터 크기, 길 찾기, 재질, 광량, 안개, HUD를 수정한다.

### 3. P1 2–4장

- 기존 `roomWaves`, 입장 유예, 리스폰, 결정 흐름을 유지한다.
- 장마다 최소 세 공간, 고유 이동 구조, 단서 상호작용, 중간 퍼즐, 보스/탈출을 추가한다.
- 이전 장 결정은 다음 장 대사, 적 조합, 증거 접근 중 최소 두 곳에 영향을 준다.

### 4. P2 5–6장

- 공용 캠페인 장면을 2–5장으로 일반화해 증언 보관소를 구현한다.
- 현재 마지막 방송의 chapter-5 결합점을 한 수직 슬라이스에서 모두 chapter-6으로 옮긴다.
- 6장은 릴레이, 보호 프로토콜, 최종 코어 전투 후 가린 방송/원본 공개/봉인을 결정한다.

### 5. P3 제품 완성

- 타이틀, 새 게임/이어하기, 1–6장 지도, 사운드·모션·화질, 조작 안내를 구현한다.
- 장별 결정·증거·결과·시도 상태를 보여 주는 개인정보 없는 교사용 조사 보고서와 인쇄 CSS를 구현한다.

### 6. P4 최적화·배포

- 장별 lazy load/prefetch/dispose, 중복 애니메이션·재질 제거, 모바일 저화질, service-worker cache migration을 검증한다.
- 초기 다운로드, 장별 자산, 번들, draw calls, triangles, p95, heap을 최신 SHA 기준으로 기록한다.

## 검증 행렬

- Node: H-17 전용과 legacy를 분리 집계하되 총 테스트 수를 줄이지 않는다.
- 브라우저: 새 게임 1→6, 세 결말, 장별 이어하기, v4 마이그레이션, 오프라인, context loss.
- 입력: 키보드와 터치 각각 이동·공격·회피·반사·추적·확보·소거·설정·보고서까지 완주.
- 접근성: 44px, focus-visible, reduced motion, 자막, 비색상 상태, CJK 줄바꿈, 보고서 인쇄.
- 시각: 모든 장/핵심 상태의 fresh capture, P0 레퍼런스 동일 크기 비교, 독립 visual QA blocking 0.
- 회귀: `npm test`, `npm run build`, `npm run smoke`, `npm run e2e`, `npm run slice:gate`, console/asset error 0.
